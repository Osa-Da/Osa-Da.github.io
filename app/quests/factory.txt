Файл data.js — это один JavaScript-файл, содержащий единственную константу const GAME = { ... }; всё, что не описано ниже, движок игнорирует. В корне объекта GAME есть пять полей: id (строка, обязательна, латиница/цифры/дефис — короткий идентификатор игры, служит префиксом ключей в localStorage, игроку не виден), title (строка, обязательна — заголовок игры, показывается в шапке и в document.title), glossary (массив статей справочника, необязателен — движок читает как GAME.glossary || [], редактор всегда пишет пустым массивом, если статей нет), library (объект с четырьмя массивами, см. ниже; на рантайме движок читает только library.codes, остальные три массива нужны исключительно редактору для round-trip ссылок) и characters (словарь персонажей, где ключ — код для входа в игру в UPPERCASE; может быть пустым объектом). Поле glossary содержит массив объектов вида { icon, title, description, mechanic }, где title и description обязательны, icon — имя иконки Lucide (по умолчанию "info"), а mechanic — необязательный текст, который рендерится отдельным синим блоком под описанием.

Объект library содержит четыре массива: features, abilities, quests и codes. По движку обязателен только codes; остальные три читаются лишь редактором и нужны для восстановления ссылок _libId/_lib при импорте — для чисто рантаймового data.js их можно опустить, но редактор их всегда пишет (пустыми, если элементов нет). Массивы features и abilities хранят переиспользуемые особенности и способности одинаковой структуры: { id, name, description, icon, details }, где id — уникальная строка (префикс f_ для особенностей, a_ для способностей; движком не читается, но нужен редактору, потому что на него ссылается _libId в элементах персонажа), name — название, по которому движок матчит прогресс игрока (переименование сбрасывает разблокировки у всех игроков), description — что делает, icon — необязательное имя иконки Lucide (по умолчанию "star" или "zap"), details — необязательный дополнительный текст вроде стоимости или условий. Массив quests хранит задания: { id, title, description, details, successfulCodes, failedCodes, rewards, rewardsDescription }, где id — уникальная строка с префиксом q_ (движком не читается), title — название (по нему матчится прогресс), description — что нужно сделать, details — необязательные уточнения, successfulCodes — массив кодов UPPERCASE, завершающих задание, failedCodes — массив кодов, проваливающих задание, rewards — необязательный объект вида { COMPLETED?, FAILED? } со строками-наградами (движок рендерит только COMPLETED и только когда задание в статусе «Завершено»), rewardsDescription — необязательный объект той же формы с текстовым описанием награды, которое рендерится над строкой из rewards.COMPLETED.

Массив codes в библиотеке хранит глобальные коды (применяются ко всем персонажам). Каждый код — объект с обязательным полем key (строка в UPPERCASE — то, что вводит игрок; движок ищет глобальный код именно по key, поэтому регистр критичен: движок вызывает .toUpperCase() на вводе игрока, но сверяет как есть) и опциональным id (строка с префиксом lc_ — движком не читается, редактор пишет для единообразия). Поведение кода определяется одним из пяти взаимоисключающих признаков, причём приоритет при обработке: targets > type > reveal. Варианты: (1) reveal — просто показать текст, { key, type: "reveal", reveal: "Текст сообщения" }, причём если в объекте есть только reveal, поле type можно опустить; (2) features — открыть особенность, { key, type: "features", name, description, icon?, details? }, может иметь служебное поле _libRef (или $libRef — старый синоним) со ссылкой на элемент библиотеки, но движок читает только сами поля name/description/icon/details, поэтому при ручной генерации их надо дублировать, не полагаясь на _libRef — иначе движок разблокирует особенность с undefined-полями и молча ничего не покажет; (3) ability — то же самое, но type: "ability"; (4) quest — открыть задание, { key, type: "quest", name, icon?, content: { description, details? } }; (5) targets — каскад, { key, targets: ["КОД1", "КОД2"] }, который по очереди применяет указанные коды. Особым случаем является массив в type, например type: ["ability", "features"] — движок разблокирует и то и другое одной командой; редактор такого не умеет, но движок поддерживает.

Словарь characters содержит объекты персонажей, ключом выступает код для входа (UPPERCASE, обычно латиница). По движку строго обязательны только name (имя), title (роль/подзаголовок) и faction (просто отображаемая строка — движок её не интерпретирует, только рисует под именем) — у этих полей нет fallback, при отсутствии в HTML попадёт undefined. Остальные текстовые поля необязательны: legend (публичная легенда — рендерится как || "—"), teamInfo (цель команды — тоже с fallback || "—"), trueNature (тайная правда — при пустом значении блок скрывается), fact (что известно с самого начала — при пустом блок тоже скрывается). Обязательны массивы features, abilities, quests, inventory (могут быть пустыми — движок читает их как || []) и объект codeSystem (может быть пустым). Элементы features/abilities внутри персонажа имеют ту же структуру, что в библиотеке, но без id, и могут содержать служебные поля _libId (новый синоним) или $lib (старый) — это ссылка на элемент библиотеки, которую движок игнорирует, но редактор использует для обратного импорта; при экспорте редактор пишет _libId. Элементы quests внутри персонажа тоже совпадают по структуре с библиотечными заданиями и тоже без id, с опциональным _libId. Элементы inventory — простые объекты { icon, name, description }, где icon и name обязательны, description необязателен, а id у них нет вовсе (редактор держит id в памяти, но cleanItem его стирает при экспорте). Объект codeSystem персонажа устроен как словарь, где ключ — UPPERCASE-код, а значение — объект кода без id и без key (ключ уже в имени поля), поддерживающий все пять типов из библиотеки, и дополнительно для кодов типа quest движок умеет читать successfulCodes/failedCodes прямо на объекте кода, хотя это редкий случай.

Чего в data.js быть не должно: поля GAME.factions (фракции как отдельная сущность — редактор при экспорте «впекает» их в персонажей, подставляя готовые faction и teamInfo), а также служебных меток редактора _lib, _fac, _fromFaction. Поля _libRef/$libRef (у кодов) и _libId/$lib (у элементов персонажа) в файле допустимы — движок их не читает, редактор читает любые из двух вариантов на импорте и пишет новые на экспорте. Всё остальное, что не описано выше, молча игнорируется. Ключевые правила для генерации: прогресс игрока в localStorage привязан к именам — для features/abilities это name, для quests — title, поэтому переименование сбрасывает разблокировки у всех; коды работают в двух местах, library.codes — глобальные для всех персонажей, characters[CODE].codeSystem — персональные, приоритет у персональных (движок сначала ищет в codeSystem, потом в библиотеке); раздел отображения (жёлтый «Особенности», синий «Способности», зелёный «Задания») зависит от type кода, а не от того, в каком массиве библиотеки лежит элемент; код без name (для типов, где name нужен) игнорируется — при type: "features" и пустом name движок вернётся из applyCode на первой же проверке; key всегда UPPERCASE; дубликаты имён внутри одного персонажа недопустимы, потому что движок хранит статусы разблокировок и заданий по именам, и два элемента с одинаковым именем будут делить один флаг в localStorage.

# МЕХАНИКИ ИГРЫ «ТАЙГА: КРУШЕНИЕ 234»
## Версия 0.5 — гражданские и соло объединены

---

## 1. ЦИКЛ И ФАЗЫ

**Цикл = одни сутки в тайге.**

- **День** — примерно 30 минут.
- **Ночь** — примерно 15 минут.
- Если все проголосовали раньше — ведущий может закончить ночь досрочно.
- Точные цифры ведущий может менять под себя.

### Фазы
1. **Утро** — ведущий объявляет погоду на день и события ночи.
2. **День** — перемещение, поиск, торговля, общение, голосования.
3. **Вечер** — ведущий объявляет погоду на ночь и события.
4. **Ночь** — еда, голосования, сон. Кто не в доме — рискует.

---

## 2. СТАТУСЫ

### Сыт
- Получен после еды.
- Длится одни сутки.
- Даёт право голосовать, инициировать голосования, участвовать в конфликтах.

### Ослаблен
Это **один общий дебафф**. Он заменяет собой «голоден».

**Источники ослабления:**
- не ел сутки;
- голосовал — любая сторона, любой итог;
- участвовал в конфликте — любая сторона;
- инициировал голосование — даже если оно провалилось;
- не успел в дом до сумерек.

**Что даёт ослабление:**
- нельзя инициировать голосование;
- нельзя голосовать;
- нельзя участвовать в конфликтах;
- можно быть жертвой голосования только один раз за ночь.

**Как снимается:**
- едой;
- способностью персонажа;
- спадает утром, если получен от голосования или конфликта;
- если от голода — не спадает, пока не поест.

**Если ослабленный не поест вторые сутки подряд — он умирает.**

### Мёртв
- Игрок надевает чёрные очки.
- Не участвует в игре.
- Может говорить только с другими мёртвыми.
- Его вещи остаются на локации, где он погиб.
- Мёртвого можно обыскать. Инициатор забирает весь конверт.

### Изолирован
- Игрок надевает белые очки.
- Не участвует одну ночь и следующий день.
- Не голосует, не инициирует, не участвует в конфликтах.
- Его игнорируют все живые.
- Через цикл возвращается.
- Вещи остаются при нём.
- Если у изолированного нет еды — один из изолирующих обязан отдать ему одну еду.

## 3. ПОГОДА

**По умолчанию днём теплее, чем ночью.**

| Погода | День | Ночь |
|---|---|---|
| **Обычная** | Можно на улице в тёплой одежде | На улице метель. Без укрытия — смерть |
| **Оттепель** | Можно на улице без одежды | Можно на улице в тёплой одежде |
| **Метель** | На улице — смерть | На улице — смерть |

Дом безопасен всегда, если дверь закрыта.

## 4. СОБЫТИЯ

- **Волки** — приходят ночью или днём. На улице — смерть. В самолёте можно спрятаться. В доме безопасно, если дверь закрыта.
- **Медведи** — приходят ночью или днём. На улице — смерть. В самолёте можно спрятаться. В доме безопасно, если дверь закрыта.
- **Метель** — длится одну фазу. После метели ведущий обновляет тайники: старые предметы остаются, новые появляются.

## 5. ЛОКАЦИИ

| Локация | Особенности |
|---|---|
| **Дом** | Безопасен всегда, кроме открытой двери во время метели или зверей |
| **Улица** | Подчиняется погоде. Днём — в тёплой одежде. В оттепель — без одежды. Ночью — только в тёплой одежде или в оттепель |
| **Самолёт** | Погода как на улице. Внутри можно спрятаться от зверей. Здесь детали рации и багажный отсек |

## 6. ЕДА

- Одна единица еды = сыт на одни сутки.
- Не ел сутки — ослаблен.
- Не ел двое суток — смерть.
- Еда может быть: консервы, сухпаёк, мясо, рыба, человеческое мясо.
- Еду можно найти, купить, украсть, получить в обмен, снять с убитого.

## 7. ГОЛОСОВАНИЕ

### Правила
- Проходит ночью.
- Любой живой игрок может инициировать, если он не ослаблен.
- **Тот, кто инициировал голосование — становится ослабленным, независимо от итога.**
- Все, кто голосовал — становятся ослабленными.
- Пилот может инициировать два раза за ночь.
- Богач не может инициировать, но может заплатить другому.

### Пороги
Обозначения:
- **N** — количество живых на момент голосования.
- **↑** — округление вверх.
- **За** — голоса «за».
- **Против** — голоса «против».

| Действие | Минимум «За» | Условие | Минимум живых |
|---|---|---|---|
| **Убить** | N / 4 ↑, но не меньше 2 | За > Против | 3 |
| **Изолировать** | N / 5 ↑, но не меньше 1 | За ≥ Против | 2 |
| **Кража** | N / 6 ↑, но не меньше 1 | За ≥ Против | 2 |
| **Обыск** | N / 6 ↑, но не меньше 1 | За ≥ Против | 2 |
| **Собрать рацию** | 1 | За ≥ Против | — |

### Кворум
Голосование состоялось, если проголосовало хотя бы половина живых.
Если кворума нет — голосование провалилось, но инициатор всё равно ослаблен.

### Приоритет
Если два голосования начались одновременно — приоритет у того, чей номер на конверте больше.

### Жертва
- Может сопротивляться — тогда становится ослабленной.
- Может не сопротивляться — тогда не становится ослабленной.
- Ослабленный может быть жертвой только один раз за ночь.

---

## 8. КОНФЛИКТ

- Начинается, если «За» и «Против» равны.
- Инициатор и жертва подкидывают монетку.
- Кто отгадал — тот победил.
- Обе стороны становятся ослабленными.
- Если жертва не сопротивлялась — конфликта нет.

### Особые случаи
- Сытый против ослабленного — сытый побеждает автоматически.
- Силач бросает монетку дважды и выбирает лучший результат.

---

## 9. ОБЫСК И КРАЖА

### Обыск
- Инициатор смотрит конверт жертвы.
- Видит все предметы.
- Может выбрать предмет для кражи, если кража тоже прошла.

### Кража
- У жертвы крадут случайный предмет.
- Если жертву ранее обыскали — крадут предмет на выбор.
- Украденный предмет переходит инициатору.

---

## 10. ПОИСК ПРЕДМЕТОВ

- Ведущий раскидывает предметы по локациям, пока идут голосования.
- Утром игроки могут искать.
- Старые предметы остаются на прежних местах.
- После метели или нападения зверей ведущий добавляет новые.
- В метель или при зверях поиск вне дома запрещён.

---

## 11. ТЁПЛАЯ ОДЕЖДА

- Всего пять комплектов на игру.
- Без тёплой одежды выход на улицу ночью, в метель или во время зверей — смерть.
- В оттепель днём можно без одежды.
- Если днём была оттепель — ночью можно без одежды.
- Тёплую одежду можно купить, украсть, получить в обмен, найти.

---

## 12. ДЕНЬГИ (CR)

- Общая валюта обмена.
- Разбросаны по территории и обломкам.
- Можно купить еду, одежду, информацию, голос, жизнь.
- Богач — 50 CR.
- Главарь — 40 CR.
- Остальные — 10–20 CR.
- Разбросано по локациям — 40 CR.

---

## 13. КАННИБАЛИЗМ

- Персонаж с особенностью «Каннибализм» может есть человеческое мясо.
- Если персонаж участвует в убийстве — он становится сытым.
- Три единицы еды достаются участникам убийства с каннибализмом.

---

## 14. РАЦИЯ И ФИНАЛ

### Сбор деталей
- Нужно собрать четыре детали рации.
- Если изначально игроков больше пятнадцати — пять деталей.
- Детали прячет ведущий.
- Детали могут повторяться, но нужно собрать уникальные.
- Детали можно найти, украсть, получить в обмен.

### Сигнал
- Когда у игрока все детали — он может инициировать голосование «Собрать рацию и подать сигнал».
- Порог: один «За», один «Против».
- Если голосование прошло — сигнал подан.

### Спасатели
- После подачи сигнала должны пройти сутки.
- Через сутки спасатели прибывают.
- Все выжившие спасаются.
- Незаконники идут в тюрьму.
- Их могут оправдать персонажи со способностью «Не последний человек».

## 15. УСЛОВИЯ ПОБЕДЫ

| Фракция | Условие |
|---|---|
| **Экипаж** | Спасти всех пассажиров, починить рацию, вызвать подмогу |
| **Банда** | Найти чип, собрать припасы, сбежать без спасателей |
| **Местные** | Добраться до юга, найти документы, выжить |
| **Одиночки** | Достичь личной цели и выжить (или сбежать, если это часть цели) |

**Гражданские и Соло — одна фракция «Одиночки».**

## 17. ЧТО НЕ ЯВЛЯЕТСЯ МЕХАНИКОЙ

- **Суд в финале** — это эпилог, а не отдельная механика.
- **Лесник** — просто ведущий, в игру не вмешивается.
- **Обмен** — свободный, по договорённости.
- **Скрытые действия** — убраны.
- **«При смерти»** — убрано.
- **«Голоден»** — объединено с «Ослаблен».
- **Гражданские и Соло** — объединены в «Одиночки».

1. Доработать персонажей до уровня Ганса и Греты.

3. Расширить список предметов, если нужно.
4. Сделать карточки событий для ведущего.
5. Прописать финальные сцены для каждой роли.

Скажи, что делаем дальше: **персонажи**, **предметы**, **карточки** или **финалы**.
